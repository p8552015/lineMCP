# 開發者程式碼品質實用指南

## 🚀 快速修復手冊

### 常見錯誤類型與快速解決方案

#### 1. E501 - 行長度過長 (88字符限制)

**問題識別**:
```python
# ❌ 錯誤：超過 88 字符
def very_long_method_name_with_many_parameters(param1, param2, param3, param4, param5):
    pass
```

**修復方案**:
```python
# ✅ 方案1：參數分行
def very_long_method_name_with_many_parameters(
    param1, param2, param3, 
    param4, param5
):
    pass

# ✅ 方案2：字符串分割
long_message = (
    "這是一個很長的訊息，需要分割成多行"
    "以符合程式碼風格要求"
)

# ✅ 方案3：f-string 分割
logger.info(
    f"服務器 {server_name} 啟動成功 "
    f"(PID: {process_id})"
)
```

#### 2. N818 - 異常類別命名

**問題識別**:
```python
# ❌ 錯誤：缺少 Error 後綴
class ValidationException(Exception):
    pass
```

**修復方案**:
```python
# ✅ 正確：添加 Error 後綴
class ValidationError(Exception):
    pass
```

#### 3. F401 - 未使用的導入

**問題識別**:
```python
# ❌ 錯誤：導入了但未使用
import os
import sys  # 實際未使用
```

**修復方案**:
```python
# ✅ 正確：只導入需要的模組
import os
```

#### 4. E402 - 導入位置錯誤

**問題識別**:
```python
# ❌ 錯誤：導入不在檔案頂部
import sys
sys.path.append('.')

import structlog  # 應該在頂部
```

**修復方案**:
```python
# ✅ 正確：將所有導入移到頂部
import sys
import structlog

sys.path.append('.')
```

## 🛠️ 開發工具配置

### 1. VS Code 配置

創建 `.vscode/settings.json`:
```json
{
    "python.linting.enabled": true,
    "python.linting.ruffEnabled": true,
    "python.formatting.provider": "black",
    "python.formatting.blackArgs": ["--line-length=88"],
    "editor.formatOnSave": true,
    "editor.rulers": [88],
    "python.linting.ruffArgs": ["--line-length=88"],
    "python.linting.ruffPath": "poetry run ruff"
}
```

### 2. Pre-commit Hooks 設置

創建 `.pre-commit-config.yaml`:
```yaml
repos:
  - repo: https://github.com/psf/black
    rev: 23.3.0
    hooks:
      - id: black
        args: [--line-length=88]
        
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.0.270
    hooks:
      - id: ruff
        args: [--fix, --exit-non-zero-on-fix]
        
  - repo: https://github.com/pre-commit/mirrors-mypy
    rev: v1.3.0
    hooks:
      - id: mypy
        additional_dependencies: [types-all]
```

安裝命令:
```bash
pip install pre-commit
pre-commit install
```

### 3. 快速修復腳本

創建 `scripts/fix-code-quality.sh`:
```bash
#!/bin/bash
set -e

echo "🔧 自動修復程式碼品質問題..."

# 1. 自動修復 Ruff 可修復的問題
echo "📝 修復 Ruff 問題..."
poetry run ruff check src/ --fix

# 2. Black 格式化
echo "🎨 執行 Black 格式化..."
poetry run black src/

# 3. 最終檢查
echo "✅ 執行最終檢查..."
poetry run ruff check src/

echo "🎉 程式碼品質修復完成！"
```

使用方法:
```bash
chmod +x scripts/fix-code-quality.sh
./scripts/fix-code-quality.sh
```

## 🎯 常見場景解決方案

### 場景 1: 長日誌訊息

```python
# ❌ 問題
logger.info(f"用戶 {user_id} 在 {timestamp} 執行了 {action} 操作，結果：{result}")

# ✅ 解決方案
logger.info(
    f"用戶 {user_id} 在 {timestamp} 執行了 {action} 操作，"
    f"結果：{result}"
)
```

### 場景 2: 長方法簽名

```python
# ❌ 問題
def process_machine_data(machine_id, start_time, end_time, include_faults, include_maintenance):
    pass

# ✅ 解決方案
def process_machine_data(
    machine_id: str,
    start_time: datetime,
    end_time: datetime,
    include_faults: bool = True,
    include_maintenance: bool = True,
):
    pass
```

### 場景 3: 長 SQL 查詢

```python
# ❌ 問題
query = "SELECT machine_id, status, temperature FROM machines WHERE status = 'running' AND temperature > 80"

# ✅ 解決方案
query = (
    "SELECT machine_id, status, temperature FROM machines "
    "WHERE status = 'running' AND temperature > 80"
)
```

### 場景 4: 複雜條件判斷

```python
# ❌ 問題 (SIM102)
if server_available:
    if config.auto_connect:
        connect_to_server()

# ✅ 解決方案
if server_available and config.auto_connect:
    connect_to_server()
```

## 🔧 故障排除

### 問題：Pre-commit hooks 失敗

**原因**: Poetry 環境問題或工具未安裝

**解決方案**:
```bash
# 重新安裝 pre-commit
pip install --upgrade pre-commit
pre-commit clean
pre-commit install

# 手動測試
pre-commit run --all-files
```

### 問題：Ruff 檢查在 CI 中失敗但本地通過

**原因**: 版本不一致或配置差異

**解決方案**:
```bash
# 確保版本一致
poetry show ruff
poetry run ruff --version

# 清理並重新檢查
poetry run ruff clean
poetry run ruff check src/
```

### 問題：MyPy 類型檢查錯誤

**常見解決方案**:
```python
# 1. 添加類型注解
def process_data(data) -> dict:  # ❌
def process_data(data: list[dict]) -> dict:  # ✅

# 2. 使用 TYPE_CHECKING
from typing import TYPE_CHECKING
if TYPE_CHECKING:
    from some_module import SomeClass

# 3. 忽略特定錯誤（謹慎使用）
result = some_complex_operation()  # type: ignore
```
