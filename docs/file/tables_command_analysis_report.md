## 🧩 樣板 1：檔案在專案中扮演的角色

【文件角色摘要】
- 📌 **主要功能與責任**：
    - **實現 `/tables` 指令**。它提供了兩種功能模式：
        1.  **不帶參數**：列出資料庫中所有的資料表名稱。
        2.  **帶有資料表名稱**：顯示指定資料表的詳細結構（Schema），包括欄位名稱、資料型態、約束，並附帶該表的總行數。
    - **作為資料庫的「目錄」和「藍圖」**。讓開發者或進階用戶能夠在不離開聊天介面的情況下，快速了解資料庫的結構，為後續的 `/sql` 查詢或自然語言查詢提供必要的上下文。

- 🧠 **在系統架構中的定位（上層來源與下游依賴）**：
    - **定位**：**指令模式**中的一個具體**指令處理器 (Concrete Command Handler)**。
    - **上層來源**：被 `domain.CommandExecutor` 呼叫。
    - **下游依賴**：
        1.  `domain.CommandContext`: 用於獲取 `mcp_client`。
        2.  `services.unified_mcp_client.MCPResponseParser`: 用於解析 MCP 回傳的結果。
        3.  `domain.exceptions` & `services.error_handlers.ErrorContext`: 用於統一的錯誤處理和日誌記錄。

- 🔁 **是否處理通訊 / 外部互動**：
    - **是**。它透過 `mcp_client` 對後端 `sqlite` 工具發起多次查詢，例如 `SELECT name FROM sqlite_master` (列出所有表) 和 `PRAGMA table_info(...)` (查詢表結構)。

- ⚙️ **是否處理設定管理**：
    - **否**。

- 🧪 **是否負責資料驗證、格式轉換或協定解析**：
    - **是**。
        1.  **參數解析**：`handle` 方法會檢查 `args` 來決定執行哪種功能。
        2.  **格式轉換**：`_list_all_tables` 和 `_get_table_schema` 方法的核心職責就是將資料庫回傳的、原始的、列表化的字典數據，**轉換**成對用戶友善、格式優美的文字報告。

- 💡 **是否涉及平台相依性、跨平台兼容性、錯誤恢復**：
    - **是**。
        1.  主流程 `handle` 方法使用 `try...except` 塊來捕獲所有潛在的資料庫錯誤，並將其包裝成統一的 `DatabaseException` 向上拋出。
        2.  在 `_get_table_schema` 中，對「查詢資料表行數」的 `try...except` 處理是一個**亮點**。它將這一個可能失敗的非核心操作（例如對虛擬表執行 COUNT 可能出錯）與核心的表結構查詢分開處理，保證了即使行數查詢失敗，用戶依然能看到最重要的表結構資訊，增強了指令的**韌性**。

- 🎯 **實用比喻**：
    - 它就像是**圖書館的電子檢索系統**。你可以先搜尋「所有書架的列表」(`/tables`)，這會告訴你圖書館裡有「歷史區」、「科學區」、「文學區」等。然後你可以進一步查詢「科學區書架的詳細資訊」(`/tables science_shelf`)，系統會告訴你這個書架上有幾本書、每本書的標題、作者和分類號（欄位結構）。

## 🧩 樣板 2：有哪些類別，以及創建目的與結構特性

【類別分析】
- **類別名稱**：`TablesCommandHandler`
- 📌 **創建目的**：
    - 將所有與資料庫元數據（表列表、表結構）查詢和展示相關的邏輯封裝起來。
- 🧭 **使用場景**：由 `CommandExecutor` 呼叫。
- 📂 **管理資源**：不管理任何外部資源。
- 🧩 **內含哪些關鍵方法與邏輯功能**：
    - `handle()`: 根據參數路由到不同的功能方法。
    - `_list_all_tables()`: 實現列出所有資料表的功能。
    - `_get_table_schema()`: 實現獲取單一資料表詳細結構的功能，並巧妙地結合了行數查詢。
- 💡 **設計考量**：
    - **用戶體驗 (UX)**：在報告的結尾提供了下一步操作的提示（例如 "💡 查看資料表結構：/tables <資料表名稱>"），引導用戶進行後續操作，這是一個很好的設計細節。
    - **關注點分離**：清晰地將「列出所有」和「顯示單一」兩種不同的業務場景分離到各自的方法中。
