## 🧩 樣板 1：檔案在專案中扮演的角色

【文件角色摘要】
- 📌 **主要功能與責任**：
    - **作為指令模式的「呼叫者」(Invoker)**。它的核心職責是接收原始的文字訊息，並協調整個指令的生命週期：
        1.  **註冊**：在初始化時，它會實例化所有具體的指令處理器 (`CommandHandler`) 並將它們註冊到 `CommandRegistry`。
        2.  **解析**：使用 `parse_command` 函式將文字訊息解析成結構化的指令物件（名稱 + 參數）。
        3.  **查找**：從 `CommandRegistry` 中根據指令名稱找到對應的處理器。
        4.  **驗證**：呼叫處理器自身的 `validate_args` 方法進行參數驗證。
        5.  **執行**：呼叫處理器的 `handle` 方法來執行真正的業務邏輯。
- 🧠 **在系統架構中的定位（上層來源與下游依賴）**：
    - **定位**：位於**領域層 (`domain`) 的核心協調器**。它位於應用服務（如 `MessagingService`）和具體指令實現（`commands/`）之間，是連接兩者的橋樑。
    - **上層來源**：被 `MessagingService` 所呼叫，當 `MessagingService` 判斷一條訊息是指令時，就會將其交給 `CommandExecutor` 處理。
    - **下游依賴**：
        1.  `domain.command_handler`：深度依賴指令處理器的抽象和註冊表。
        2.  `models.commands.parse_command`: 依賴此輔助函式來解析文字。
        3.  `domain.exceptions`: 用於在發生錯誤時拋出標準化的領域異常。
        4.  **所有具體的指令處理器** (`src/commands/*`)：在 `_register_all_commands` 方法中，它**直接匯入並實例化**了所有指令，這是一個非常明確的依賴關係。

- 🔁 **是否處理通訊 / 外部互動**：
    - **否**。它將所有外部互動都委託給下游的具體指令處理器。

- 💡 **是否涉及平台相依性、跨平台兼容性、錯誤恢復**：
    - **是，並且非常出色**。`execute_command` 中的 `try...except` 區塊是錯誤處理的核心。它能捕獲 `KeyError`（當指令不存在時）並提供有用的回饋，也能捕獲任何在指令執行中發生的其他異常，並將其記錄下來再向上拋出。這種模式確保了單一指令的失敗不會弄髒日誌或讓系統崩潰。

- 🎯 **實用比喻**：
    - 它就像是**一家餐廳的總機服務生**。
        1.  **初始化 (`initialize`)**: 上班時，服務生會拿到一份今天所有廚師（指令處理器）的名單和他們各自的拿手菜（指令名稱）。
        2.  **執行 (`execute_command`)**: 客人（用戶）遞上一張手寫的訂單（文字訊息）。服務生首先解讀訂單 (`parse_command`)，看懂客人點的是「宮保雞丁」還是「魚香肉絲」。然後他在廚師名單 (`CommandRegistry`) 中找到專門做這道菜的廚師。他將訂單交給廚師，並在廚師開始做之前確認一下特殊要求是否合理 (`validate_args`)。最後，廚師開始烹飪 (`handle`)。如果客人點了一道菜單上沒有的菜 (`KeyError`)，服務生會禮貌地告知。

## 🧩 樣板 2：有哪些類別，以及創建目的與結構特性

【類別分析】
- **類別名稱**：`CommandExecutor`
- 📌 **創建目的**：
    - **為了將指令的「呼叫邏輯」與「業務邏輯」分離**。它讓 `MessagingService` 不需要知道任何關於具體指令的細節，只需要將指令訊息丟給 `CommandExecutor` 即可。
- 🧭 **使用場景**：在應用啟動時由 `MessagingService`（或相關工廠）創建一個單例，並在每次需要處理指令時呼叫其 `execute_command` 方法。
- 📂 **管理資源**：它不直接管理資源，但它**管理著所有指令處理器的生命週期**（創建和註冊）。
- 🧩 **內含哪些關鍵方法與邏輯功能**：
    - `initialize()` / `_register_all_commands()`: **指令的發現與註冊中心**。這是系統擴充性的關鍵，新增指令只需要修改這個列表。
    - `execute_command()`: **核心執行流程**。完美地體現了指令模式的呼叫者角色。
- 💡 **設計考量**：
    - **延遲初始化 (Lazy Initialization)**：透過 `_initialized` 旗標，確保了註冊所有指令這個可能較重的操作只在第一次需要執行指令時發生一次，而不是在應用啟動時就立即執行。
    - **集中化註冊**: 將所有指令的實例化都集中在 `_register_all_commands` 方法中，使得查看系統支援哪些指令變得非常容易，提高了可維護性。
    - **依賴傳遞**: 它在初始化時接收 `CommandContext`，並在創建所有指令處理器時將其傳遞下去，確保了所有指令都能獲得它們需要的依賴。
