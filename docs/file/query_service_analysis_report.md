## 🧩 樣板 1：檔案在專案中扮演的角色

【文件角色摘要】
- 📌 **主要功能與責任**：
    - **作為所有 SQL 查詢的統一執行入口**。它接收來自其他服務（如 `ApplicationFacade`）的 SQL 查詢請求。
    - **提供查詢生命週期管理**：包括**安全驗證** (`_validate_query`)、**快取** (`_query_cache`)、**統計** (`_query_stats`) 和**歷史記錄** (`_query_history`)。
    - **協調底層服務**：透過 `mcp_client` 與實際執行查詢的子進程通訊，並使用 `response_parser` 解析結果。
    - **封裝複雜性**：將查詢的快取邏輯、安全檢查、效能統計等複雜但通用的功能封裝起來，讓上層服務可以專注於業務，而不用關心這些細節。

- 🧠 **在系統架構中的定位（上層來源與下游依賴）**：
    - **定位**：一個專門的**應用服務**，負責處理所有與資料查詢相關的跨功能需求。
    - **上層來源**：被 `ApplicationFacade` 呼叫，以執行高層次的查詢操作。
    - **下游依賴**：
        1.  `mcp_client_factory`: 用於獲取與後端 MCP 通訊的客戶端。
        2.  `db_service` (未使用，可能是遺留代碼或未來用途): 推測是用於更直接的資料庫操作。
        3.  `response_parser`: 用於解析從 MCP 回傳的原始結果。
        4.  `domain.exceptions`: 用於拋出標準化的領域異常。

- 🔁 **是否處理通訊 / 外部互動**：
    - **是**。它透過 `mcp_client` 與一個可能是 `sqlite` 的子進程進行**跨進程通訊**來執行查詢。

- ⚙️ **是否處理設定管理**：
    - **否**。但它內部有一些硬編碼的設定值，如 `_cache_ttl_seconds`（快取時間）。

- 🧪 **是否負責資料驗證、格式轉換或協定解析**：
    - **是**。`_validate_query` 執行了非常重要的**安全驗證**，防止 SQL 注入。`response_parser` 被用來**解析**來自 MCP 的回應。

- 💡 **是否涉及平台相依性、跨平台兼容性、錯誤恢復**：
    - **是**。`execute_sql_query` 方法中的 `try...except` 提供了強大的**錯誤恢復**機制。它不僅捕獲錯誤，還更新統計數據、記錄歷史，並將通用異常轉換為特定的 `DatabaseException`。

- 🔐 **是否與授權、安全、敏感操作有關**：
    - **是**。`_validate_query` 是這個服務最關鍵的安全部分，它透過白名單和黑名單關鍵字來防止惡意或破壞性的 SQL 查詢被執行。

- 🎯 **實用比喻**：
    - 它就像是**圖書館裡經驗豐富的資深管理員**。當有人要查資料時（`execute_sql_query`），管理員會：
        1.  **檢查借書證** (`_validate_query`)：確保這個人有權限，並且沒有試圖去撕書或塗改。
        2.  **查詢目錄** (`_query_cache`)：看看最近是否有人查過完全相同的資料，如果有的話，直接從櫃檯拿出備份副本。
        3.  **前往書庫** (`mcp_client.call_tool`)：如果沒有快取，就親自去書庫深處把書找出來。
        4.  **整理資料** (`response_parser`)：將書中的相關段落整理成易讀的筆記。
        5.  **登記記錄** (`_update_query_stats`, `_add_to_history`)：在工作日誌上記下這次查詢，以便統計圖書館的使用情況。

## 🧩 樣板 2：有哪些類別，以及創建目的與結構特性

【類別分析】
- **類別名稱**：`QueryApplicationService`
- 📌 **創建目的**：
    - 創建一個專門處理資料庫查詢的服務，將查詢相關的所有功能（安全、快取、統計）集中管理，以符合**高內聚、低耦合**的原則。
- 🧭 **使用場景（由誰使用、何時初始化）**：
    - **由誰使用**：由 `ApplicationFacade` 透過服務工廠創建和使用。
    - **何時初始化**：在 `ApplicationFacade` 初始化時被創建。
- 📂 **管理資源**：
    - 管理記憶體中的**查詢快取字典** (`_query_cache`) 和**查詢歷史列表** (`_query_history`)。
- 🧩 **內含哪些關鍵方法與邏輯功能**：
    - `execute_sql_query()`: 核心方法，封裝了完整的查詢生命週期。
    - `_validate_query()`: 關鍵的安全檢查方法。
    - `_generate_cache_key()`, `_is_cache_expired()`, `_cache_result()`: 完整的快取管理邏輯。
    - `get_query_statistics()`: 提供豐富的內部狀態和效能指標。
- 🔄 **是否支援擴充或注入**：
    - **是**。透過依賴注入傳入 `mcp_client_factory`, `db_service`, `response_parser`，可測試性很高。
- 💡 **設計考量**：
    - **SRP**: 職責非常單一和清晰：管理 SQL 查詢。
    - **快取模式 (Cache Pattern)**：實現了完整的記憶體快取邏輯，包括鍵生成、過期檢查、寫入策略和大小限制。
    - **安全性**: `_validate_query` 體現了**安全第一**的設計原則。
    - **可觀測性**: 透過 `_query_stats` 和 `_query_history`，為系統的查詢效能提供了極佳的**可觀測性**。
