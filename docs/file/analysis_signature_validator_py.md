## 🧩 樣板 1：檔案在專案中扮演的角色

【文件角色摘要】
- 📌 **主要功能與責任**:
  - 此檔案定義了 `SignatureValidator` 類別，其**唯一且核心的職責**是驗證來自 LINE 平台的 Webhook 請求的真實性。
  - **核心職責**：
    1.  **HMAC-SHA256 驗證**: 根據 LINE 平台官方規範，使用 `channel_secret` 作為金鑰，對請求的原始本文 (raw body) 計算 HMAC-SHA256 雜湊值。
    2.  **安全比較**: 使用 `hmac.compare_digest` 這個**恆定時間比較**函式，將計算出的簽章與請求中 `X-Line-Signature` 標頭的值進行比較。這可以有效防止**時序攻擊 (Timing Attack)**。
    3.  **時間戳驗證 (防重放攻擊)**: 提供了一個可選的時間戳驗證機制。透過檢查請求的時間戳與當前伺服器時間的差距，可以拒絕過時的請求，有效防範**重放攻擊 (Replay Attack)**。
    4.  **開發便利性**: 在開發環境中，允許一個特殊的 `DEV_BYPASS_SIGNATURE` 簽章來繞過驗證，這極大地簡化了使用 `curl` 或其他工具進行本地測試的流程。

- 🧠 **在系統架構中的定位**:
  - **定位**：這是一個**安全層的守門人 (Security Gatekeeper)**。它位於應用程式的最外層，緊接在 Web 框架（FastAPI）之後。在 `webhook` 路由處理函式中，它是第一個被呼叫的元件，用於在執行任何業務邏輯之前，過濾掉所有非法的、偽造的請求。
  - **上層來源**：`routes/webhook.py` 中的 Webhook 處理端點。
  - **下游依賴**：Python 的 `hmac`, `hashlib`, `base64` 標準庫。它沒有任何專案內的其他依賴，是一個完全獨立的元件。

- 🎯 **實用比喻**:
  - `SignatureValidator` 就像是一家銀行的**保全人員**。當有人（Webhook 請求）試圖進入銀行（應用程式）時，保全人員會執行以下檢查：
    1.  檢查訪客是否持有有效的身份證件 (`X-Line-Signature`)。
    2.  將訪客的樣貌（請求 `body`）與身份證件上的照片（計算出的簽章）進行比對 (`hmac.compare_digest`)。
    3.  檢查身份證件是否過期（`_validate_timestamp`）。
    4.  如果是銀行的內部員工在進行演習（開發環境），他們可能會使用一個特殊的通行證 (`DEV_BYPASS_SIGNATURE`)。
    -   只有通過所有檢查的訪客，才能被允許進入銀行內部辦理業務（執行業務邏輯）。

## 🧩 樣板 2：有哪些類別，以及創建目的與結構特性

【類別分析】
- 類別名稱：`SignatureValidator`
  - 📌 **創建目的**: 將 LINE 平台簽章驗證的複雜邏輯**封裝**在一個獨立、可重用、可測試的單元中。
  - 🧩 **內含哪些關鍵方法與邏輯功能**:
    - `__init__()`: 接收 `channel_secret` 並將其快取為位元組，同時根據環境變數設定 `is_development` 旗標。
    - `validate()`: **核心的公開介面**。它協調了所有驗證步驟（檢查是否存在、開發繞過、時間戳、HMAC），並返回一個清晰的結果元組 `(bool, str)`，不僅告知是否有效，還告知驗證的方法或失敗的原因。這種設計對於日誌記錄和偵錯非常有幫助。
    - `_calculate_signature()`: 一個純函式，負責執行 HMAC-SHA256 計算。將其分離出來使得邏輯更清晰。
    - `_validate_timestamp()`: 另一個純函式，負責執行時間戳比較。
  - 💡 **設計考量**:
    - **安全性**:
      - **恆定時間比較**: `hmac.compare_digest` 的使用是亮點，顯示了開發者對安全細節的深刻理解。
      - **防重放攻擊**: 時間戳驗證的加入，為安全再添一層保障。
    - **職責單一**: 該類別只做一件事——驗證簽章，並且做得很好。
    - **可測試性**: 類別的依賴很少，且邏輯清晰，非常容易進行單元測試。可以輕易地測試所有分支，例如簽章缺失、簽章錯誤、時間戳過期、開發繞過等情況。

## 🧱 額外架構師視角建議補充欄位

- 🗂️ **高耦合風險**：**無**。這是一個零耦合的獨立工具類別。
- 🧪 **可測試性**：**極高**。
- 🧠 **設計優點**:
  - **清晰的返回資訊**: `validate` 方法返回 `(bool, str)`，而不僅僅是一個布林值。返回的字串（如 `"missing_signature"`, `"timestamp_expired"`, `"hmac_validation"`）為上層呼叫者提供了豐富的上下文，可以用於產生精確的錯誤日誌或 API 回應。
  - **環境區分**: `is_development` 的設計在不犧牲生產環境安全性的前提下，極大地改善了開發者體驗。
- 🧠 **重構潛力**: **無**。這個類別的實現已經非常簡潔、高效和安全，幾乎沒有重構的必要。它是一個可以被直接複製到任何需要 LINE 簽章驗證的專案中的優秀範例。
