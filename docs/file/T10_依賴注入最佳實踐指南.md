## 🏗️ 架構設計原則

### 1. 模組化工廠模式

#### 🎯 設計理念
將單一巨石工廠 (512 LOC) 拆分為專門的註冊器模組，實現 71% 程式碼減少和職責清晰分離。

#### 📋 核心組件
```
EnhancedServiceFactory (148 LOC)
├── CoreServicesRegistry (55 LOC)      - AI、格式化、解析服務
├── ApplicationServicesRegistry (76 LOC) - 應用層服務協調  
├── InfrastructureServicesRegistry (185 LOC) - 基礎設施和領域服務
└── IServiceFactory 介面 - 依賴倒置原則
```

#### ✅ 最佳實踐
```python
# ✅ 正確：模組化註冊
def register_core_services(registry: ServiceRegistry):
    """專門註冊核心服務"""
    registry.register(
        service_type=AIModelService,
        implementation=EnhancedAIModelService,
        scope=ServiceScope.SINGLETON
    )

# ❌ 錯誤：單一巨石註冊
def register_all_services(registry):
    # 所有服務混在一起，難以維護
    pass
```

### 2. 依賴倒置原則 (DIP)

#### 🎯 設計理念
高層模組依賴抽象而非具體實現，通過 IServiceFactory 介面實現解耦。

#### ✅ 最佳實踐
```python
# ✅ 正確：依賴抽象介面
class ApplicationFacade:
    def __init__(self, service_factory: IServiceFactory):
        self.service_factory = service_factory  # 依賴抽象

# ❌ 錯誤：依賴具體實現
class ApplicationFacade:
    def __init__(self, factory: EnhancedServiceFactory):
        self.factory = factory  # 依賴具體類
```

### 3. 服務生命週期管理

#### 📊 作用域類型
- **Singleton**: 全局單例（AI 服務、資料庫連接）
- **Transient**: 每次創建新實例（命令處理器）
- **Scoped**: 請求範圍內單例（用戶會話）

#### ✅ 最佳實踐
```python
# ✅ 正確：根據需求選擇作用域
registry.register(
    service_type=DatabaseService,
    scope=ServiceScope.SINGLETON,  # 共享連接池
    tags=["database", "core"]
)

registry.register(
    service_type=CommandHandler,
    scope=ServiceScope.TRANSIENT,  # 每次新建
    tags=["command", "stateless"]
)
```

## 🔄 循環依賴預防

### 1. 延遲初始化模式

#### 🎯 設計理念
在構造函數中設置 `service_factory=None`，延遲到實際使用時才創建依賴。

#### ✅ 最佳實踐
```python
# ✅ 正確：延遲初始化避免循環
class PostgresCommandHandler:
    def __init__(self, context: CommandContext):
        self.context = context
        
        if context.service_factory is None:
            self.postgres_command = None  # 延遲初始化
        else:
            self.postgres_command = PostgreSQLCommand(context.service_factory)
    
    async def handle(self, user_id: str, args: list[str]):
        # 使用時才初始化
        if self.postgres_command is None:
            await self._safe_lazy_initialization()
```

### 2. 循環依賴檢測器

#### 🎯 設計理念
使用 DFS 算法即時檢測循環依賴，提供修復建議。

#### ✅ 最佳實踐


### 3. 常見循環依賴模式及解決方案

#### 📋 模式1: ApplicationFacade ↔ ServiceFactory
```python
# ❌ 問題：相互依賴
ApplicationFacade → ServiceFactory → ApplicationFacade

# ✅ 解決：介面隔離
ApplicationFacade → IServiceFactory ← EnhancedServiceFactory
```

#### 📋 模式2: CommandExecutor ↔ CommandContext  
```python
# ❌ 問題：構造函數循環
CommandExecutor(context) → CommandContext(executor)

# ✅ 解決：延遲注入
context = CommandContext(service_factory=None)
executor = CommandExecutor(context)
context.set_service_factory(factory)  # 延遲設置
```

## 📊 性能優化策略

### 1. 服務快取與預熱

#### ✅ 最佳實踐
```python
# ✅ 正確：Singleton 服務快取
class EnhancedServiceFactory:
    def get_service(self, service_type: type):
        # 檢查循環依賴
        if not self._dependency_detector.begin_resolution(service_name):
            return None
        
        try:
            service = self._provider.get_service(service_type)
            # 註冊到檢測器
            if service:
                self._dependency_detector.register_service_type(service_name, service_type)
            return service
        finally:
            self._dependency_detector.end_resolution(service_name)
```
