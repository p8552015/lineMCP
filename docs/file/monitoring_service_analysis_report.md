## 🧩 樣板 1：檔案在專案中扮演的角色

【文件角色摘要】
- 📌 **主要功能與責任**：
    - **作為系統可觀測性的核心**。它負責**收集**、**聚合**和**報告**關於應用程式健康狀況和效能的所有資訊。
    - **執行全面的健康檢查**：不僅檢查自身的狀態，還透過 `service_context` 協調對所有其他應用服務的健康檢查，並結合系統資源（CPU、記憶體）的檢查，提供一個全域視圖。
    - **收集效能指標**：提供 `record_metric` 方法，讓其他服務可以將效能數據（如請求耗時、錯誤計數）推送給它進行統一管理。
    - **提供監控數據介面**：透過 `get_dashboard_data` 和 `get_performance_report` 等方法，為外部（如儀表板 API）提供結構化的監控數據。

- 🧠 **在系統架構中的定位（上層來源與下游依賴）**：
    - **定位**：一個專門的**應用服務**，作為一個**橫切關注點**，為系統的其他部分提供監控能力。
    - **上層來源**：
        1.  被 `ApplicationFacade` 呼叫，以執行高層次的監控操作（如健康檢查、獲取儀表板數據）。
        2.  被其他應用服務（如 `MessagingService`）呼叫，用以記錄指標 (`record_request_metrics`)。
    - **下游依賴**：
        1.  `ApplicationServiceContext`: 用於對所有已註冊的服務執行健康檢查。
        2.  `psutil` (可選): 用於獲取系統層級的資源使用情況。

- 🔁 **是否處理通訊 / 外部互動**：
    - **否**。它是一個被動的數據收集和報告中心，不主動與外部服務通訊。

- ⚙️ **是否處理設定管理**：
    - **否**。但內部有硬編碼的效能基線 (`_performance_baselines`)，這些在未來可以重構成可設定的。

- 🧪 **是否負責資料驗證、格式轉換或協定解析**：
    - **是**。它使用 `dataclass`（`PerformanceMetric`, `HealthStatus`）來驗證和結構化內部數據。同時，它將收集到的原始指標數據**轉換**成彙總的報告和儀表板數據。

- 💡 **是否涉及平台相依性、跨平台兼容性、錯誤恢復**：
    - **是**。在 `_check_system_resources` 方法中，它優雅地處理了 `psutil` 模組可能未安裝的情況 (`ImportError`)，確保了在沒有該模組的環境中，服務依然可以運行，這是一種很好的**兼容性設計**。

- 🔐 **是否與授權、安全、敏感操作有關**：
    - **否**。

- 🎯 **實用比喻**：
    - 它就像是**醫院的中央監護中心 (ICU Monitoring Station)**。
        - **連接各種感測器 (`record_metric`)**: 連接到心電圖、血壓計等各種儀器，持續接收病人的生命體徵數據。
        - **定時巡房 (`perform_comprehensive_health_check`)**: 定期檢查每間病房（其他服務）的狀況，並結合中央監護儀（系統資源）的數據，給出綜合評估。
        - **顯示在主螢幕上 (`get_dashboard_data`)**: 將所有複雜的數據匯總成醫生和護士一目了然的圖表和數字。
        - **生成交班報告 (`get_performance_report`)**: 定期生成詳細的報告，分析病人在過去一段時間內的狀況變化，並給出建議。

## 🧩 樣板 2：有哪些類別，以及創建目的與結構特性

【類別分析】
- **類別名稱**：`MonitoringApplicationService`
- 📌 **創建目的**：
    - 將所有與監控、指標、健康檢查相關的邏輯**集中**到一個地方，實現**高內聚**。
- 🧭 **使用場景**：由 `ApplicationFacade` 創建和使用。
- 📂 **管理資源**：管理記憶體中的**效能指標列表** (`_metrics`) 和**健康狀態字典** (`_health_statuses`)。
- 🧩 **內含哪些關鍵方法與邏輯功能**：
    - `record_metric()`: 記錄單個指標的底層方法。
    - `record_request_metrics()`: 記錄請求相關指標的高層次封裝。
    - `perform_comprehensive_health_check()`: 核心方法，執行全面的健康檢查。
    - `get_dashboard_data()`: 為儀表板提供彙總數據。
    - `get_performance_report()`: 生成效能報告並提供建議。
- 💡 **設計考量**：
    - **數據驅動**: 使用 `dataclass` 來定義清晰的數據結構 (`PerformanceMetric`, `HealthStatus`)，使得代碼更易於理解和維護。
    - **可觀測性**: 該服務本身就是為了實現系統的可觀測性而設計的。
    - **容錯性**: 對 `psutil` 的可選依賴處理得很好。

- **類別名稱**：`PerformanceMetric`, `HealthStatus`
- 📌 **創建目的**：
    - 使用 `dataclass` 為專案中的核心數據（指標和健康狀態）提供**清晰、強型別的定義**。
- 💡 **設計考量**：
    - 使用 `dataclass` 代替普通的字典，可以帶來**自動的 `__init__`**、**型別提示**和**更好的可讀性**，是非常現代和優秀的 Python 實踐。
