## 🧩 樣板 1：檔案在專案中扮演的角色

【文件角色摘要】
- 📌 **主要功能與責任**：
    - **實現 `/sql` 指令**。它為進階用戶或開發者提供了一個直接執行**唯讀 (read-only)** SQL 查詢的介面。
    - **作為一個強大的除錯和資料探索工具**。允許在不直接存取資料庫的情況下，對底層數據進行快速的查詢和驗證。
    - **執行安全檢查**。其最重要的職責之一是在執行前**驗證** SQL 查詢，確保只允許 `SELECT` 類型的操作，防止任何數據修改或刪除的惡意行為。

- 🧠 **在系統架構中的定位（上層來源與下游依賴）**：
    - **定位**：**指令模式**中的一個具體**指令處理器 (Concrete Command Handler)**，處理一個高權限的操作。
    - **上層來源**：被 `domain.CommandExecutor` 呼叫。
    - **下游依賴**：
        1.  `domain.CommandContext`: 用於獲取 `mcp_client` 以執行查詢。
        2.  `services.unified_mcp_client.MCPResponseParser`: 用於解析從 MCP 回傳的原始查詢結果。
        3.  `domain.exceptions`: 用於將通用資料庫錯誤包裝成一個標準化的 `DatabaseException`。
        4.  `services.error_handlers.ErrorContext`: 用於在日誌中添加更豐富的錯誤上下文，便於除錯。

- 🔁 **是否處理通訊 / 外部互動**：
    - **是**。它透過 `mcp_client.call_tool("sqlite", ...)` 與後端執行 SQL 的工具進行**跨進程通訊**。

- ⚙️ **是否處理設定管理**：
    - **否**。

- 🧪 **是否負責資料驗證、格式轉換或協定解析**：
    - **是**。
        1.  `validate_args` 方法執行**關鍵的安全性資料驗證**。
        2.  `_format_sql_result` 方法將結構化的資料庫回傳結果**轉換**為格式化的文字訊息。

- 💡 **是否涉及平台相依性、跨平台兼容性、錯誤恢復**：
    - **是**。`handle` 方法中的 `try...except` 區塊實現了**錯誤恢復**。它不僅捕獲異常，還會將其重新拋出為一個領域特定的 `DatabaseException`，這是一種優秀的實踐，它將錯誤的產生與錯誤的處理分離開來，讓更高層的統一錯誤處理器來決定如何向用戶展示錯誤。

- 🔐 **是否與授權、安全、敏感操作有關**：
    - **是，這是此檔案的核心關注點**。`validate_args` 方法透過檢查黑名單關鍵字（`drop`, `delete`, `update` 等），形成了一道關鍵的**安全屏障**，防止了潛在的 SQL 注入攻擊。

- 🎯 **實用比喻**：
    - 它就像是**一個有保全管制的銀行金庫查詢終端**。你（用戶）可以提交查詢請求（SQL 查詢），但保全（`validate_args`）會嚴格審查你的請求，確保你只是在「查詢餘額」（`SELECT`），而不是試圖「轉帳」或「取款」（`UPDATE`, `DELETE`）。查詢結果會由終端機（`_format_sql_result`）整理好後顯示給你。

## 🧩 樣板 2：有哪些類別，以及創建目的與結構特性

【類別分析】
- **類別名稱**：`SqlCommandHandler`
- 📌 **創建目的**：
    - 專門處理 `/sql` 指令，將其危險但強大的功能與其他指令嚴格隔離。
- 🧭 **使用場景**：由 `CommandExecutor` 呼叫。
- 📂 **管理資源**：不管理任何外部資源。
- 🧩 **內含哪些關鍵方法與邏輯功能**：
    - `handle()`: 協調整個流程：驗證 -> 執行 -> 解析 -> 格式化。
    - `validate_args()`: **安全守門員**。在執行任何操作前先進行安全檢查。
    - `_format_sql_result()`: **數據化妝師**。將原始數據轉換為人類可讀的格式，並進行截斷以避免訊息過長。
- 💡 **設計考量**：
    - **安全優先 (Security-First)**：將驗證邏輯放在最前面，並使用白名單外的關鍵字黑名單，體現了安全設計的考量。
    - **失敗前置 (Fail-Fast)**：如果驗證失敗，會立即回傳錯誤訊息，不會繼續執行後續邏輯。
    - **統一異常處理**: 不在本地處理異常，而是將其轉換為領域異常並向上拋出，這使得系統的錯誤處理策略非常一致和清晰。
