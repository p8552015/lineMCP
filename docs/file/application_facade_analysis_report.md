## 🧩 樣板 1：檔案在專案中扮演的角色

【文件角色摘要】
- 📌 **主要功能與責任**：
    - **提供一個統一、高層次的介面**來存取應用層的所有功能。
    - **協調**多個應用服務 (`MessagingService`, `QueryService`, `MonitoringService`) 之間的交互，將它們整合成一個單一的、有凝聚力的入口點。
    - **封裝**應用服務的初始化、生命週期管理和錯誤處理的複雜性。

- 🧠 **在系統架構中的定位（上層來源與下游依賴）**：
    - **定位**：處於**應用層的頂端**，是表示層（如 `routes`）和領域/基礎設施層之間的主要橋樑。
    - **上層來源**：主要被路由處理函式（如 `routes/webhook.py`）所呼叫，以執行業務操作。
    - **下游依賴**：
        1.  `infrastructure.IServiceFactory`: 依賴服務工廠來創建其所需的應用服務。
        2.  `application.*_service`: 依賴並組合多個應用服務來完成其高層次操作。

- 🔁 **是否處理通訊 / 外部互動**：
    - **否**。它將所有與外部的通訊都委託給下游的應用服務或更底層的服務。

- ⚙️ **是否處理設定管理**：
    - **否**。

- 🧪 **是否負責資料驗證、格式轉換或協定解析**：
    - **否**。它只負責協調和轉發請求。

- 💡 **是否涉及平台相依性、跨平台兼容性、錯誤恢復**：
    - **是**。它在 `process_message` 和 `execute_sql_query` 等主要方法中實現了 `try...except` 區塊，並與 `MonitoringService` 協作，無論成功或失敗都會記錄指標。這是一種**應用層級的錯誤處理和監控策略**。

- 🔐 **是否與授權、安全、敏感操作有關**：
    - **否**。

- 🎯 **實用比喻**：
    - 它就像是**一家高級餐廳的總管 (Maître d')**。顧客（路由層）不需要親自跑去廚房、吧檯和收銀台。他們只需要告訴總管「我要點餐」(`process_message`) 或「查詢帳單」(`get_dashboard_data`)。總管會負責協調廚房（`QueryService`）、服務生（`MessagingService`）和會計（`MonitoringService`），並將最終的結果（美味的菜餚或帳單）優雅地呈現給顧客。

## 🧩 樣板 2：有哪些類別，以及創建目的與結構特性

【類別分析】
- **類別名稱**：`ApplicationFacade`
- 📌 **創建目的**：
    - 實現**門面設計模式 (Facade Pattern)**，簡化對複雜子系統（應用服務層）的存取。
    - 降低表示層與應用服務之間的耦合度。
- 🧭 **使用場景（由誰使用、何時初始化）**：
    - **由誰使用**：主要由 `routes/webhook.py` 中的路由處理函式使用。
    - **何時初始化**：透過 `get_application_facade()` 進行**單例**且**延遲初始化**。在第一次被請求時，才會創建實例並執行其耗時的 `initialize()` 方法。
- 📂 **管理資源**：
    - 管理**應用服務物件的生命週期** (`_messaging_service`, `_query_service` 等)。它負責創建、初始化、協調和關閉這些服務。
- 🧩 **內含哪些關鍵方法與邏輯功能**：
    - `initialize()`: 核心初始化邏輯，使用服務工廠創建並初始化所有依賴的應用服務。
    - `process_message()`: 處理用戶訊息的主要入口，協調監控和訊息處理。
    - `execute_sql_query()`: 執行 SQL 查詢的入口。
    - `get_system_health()`: 獲取系統健康狀態。
    - `shutdown()`: 安全地關閉所有管理的服務。
- 🔄 **是否支援擴充或注入**：
    - **是**，非常支援。它在 `__init__` 中接收一個 `IServiceFactory` 介面的實例，這使得在測試中可以輕易地注入一個假的服務工廠。
- ⚙️ **是否耦合其他模組或設定來源**：
    - 耦合了 `IServiceFactory` 介面和具體的應用服務類別。
- 💡 **設計考量（如封裝、SRP、DI、可測試性）**：
    - **封裝**: 完美地封裝了應用服務層的內部複雜性。
    - **DI**: 透過建構函式注入 `IServiceFactory`，遵循了依賴注入。
    - **可測試性**: 由於依賴於介面 (`IServiceFactory`)，使得這個類別非常容易被單元測試。
- ✅ **是否容易測試 / 是否有測試機制設計**：是。
