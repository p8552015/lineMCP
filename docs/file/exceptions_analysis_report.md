## 🧩 樣板 1：檔案在專案中扮演的角色

【文件角色摘要】
- 📌 **主要功能與責任**：
    - **定義一套領域專用的、類型化的異常階層**。它為應用程式中所有可預見的錯誤情況建立了一個「通用詞彙表」，例如 `DatabaseQueryException`, `ValidationException` 等。
    - **將錯誤資訊分層**。這是此模組最核心的設計理念。它將提供給**開發者/日誌**的詳細技術訊息 (`message`, `details`) 與提供給**終端用戶**的友善提示 (`user_message`) 徹底分離。
    - **提供便捷的工廠函式**。例如 `create_db_error()`，它們簡化了在程式各處拋出標準化、結構化異常的過程。

- 🧠 **在系統架構中的定位（上層來源與下游依賴）**：
    - **定位**：位於**領域層 (`domain`)**，是一個**橫切關注點 (Cross-Cutting Concern)**。它處於依賴鏈的最底層，不依賴任何其他業務模組，但被幾乎所有可能發生錯誤的模組所依賴。
    - **上層來源**：被應用程式中所有需要拋出特定領域錯誤的地方引用，例如 `command_executor.py`, `sql_command.py`, 以及各種服務。
    - **下游依賴**：無。它僅依賴 Python 的標準庫。

- 💡 **是否涉及平台相依性、跨平台兼容性、錯誤恢復**：
    - **是**。這個檔案本身不「處理」錯誤恢復，但它透過提供類型化的異常，為上層模組**實現優雅的錯誤恢復**提供了必要的基礎。上層模組可以透過 `except DatabaseQueryException:` 或 `except AIServiceException:` 來捕獲特定類型的失敗，並執行相應的恢復邏輯，而不是用一個籠統的 `except Exception:` 來處理所有問題。

- 🎯 **實用比喻**：
    - 它就像是**一家醫院的「緊急應變代碼」手冊**。
        -   `BotError`: 這是手冊的總稱，代表「所有緊急情況」。
        -   `DatabaseQueryException`, `AIServiceException`: 這些是具體的緊急代碼，如「藍色代碼」（心搏停止）或「紅色代碼」（火災）。每個代碼都對應一個非常具體的狀況。
        -   **手冊內容**: 當一個「紅色代碼」被觸發時，手冊會詳細說明：
            *   給**消防員**看的資訊（`message`, `details`）：火災地點、火勢大小、涉及的化學品。
            *   給**民眾**廣播的訊息（`user_message`）："請保持冷靜，並遵循疏散路線撤離"。
        -   **工廠函式**: 就像是牆上紅色的「火警按鈕」，任何人按下它 (`create_db_error(...)`)，就能立刻觸發一個標準化的、資訊完整的火警警報。

## 🧩 樣板 2：有哪些類別，以及創建目的與結構特性

【類別分析】
- **類別名稱**：`BotError`
- 📌 **創建目的**：
    - 作為所有應用程式特定異常的**抽象基礎**。它強制所有子類都共享一個共同的結構（`user_message`, `details`, `error_code`），確保了系統中所有異常的**一致性**。
- 🧩 **內含哪些關鍵方法與邏輯功能**：
    - `__init__()`: 定義了結構化錯誤的核心屬性。
    - `to_dict()`: 提供了一個將異常物件序列化為字典的標準方法，這對於日誌記錄或將錯誤以 JSON 格式回傳給 API 消費者極其有用。

- **類別名稱**：具體的異常類別 (例如 `ValidationException`, `CommandParsingException`)
- 📌 **創建目的**：
    - 為了**標記一種特定的錯誤語意**。這使得上層的錯誤處理代碼可以根據不同的異常類型執行不同的邏輯 (`except ValidationException: ...`)。
- 💡 **設計考量**：
    - 每個具體異常類別的 `__init__` 方法都精心封裝了該錯誤類型的預設訊息和錯誤碼，使得拋出異常的程式碼可以非常簡潔，只需提供少量上下文即可。

- **函式**：便捷的工廠函式 (例如 `create_validation_error`, `create_db_error`)
- 📌 **創建目的**：
    - **提供語法糖**。它們讓建立異常實例的程式碼更具可讀性，並減少了直接與類別建構函式打交道的需要。例如，`create_db_error(...)` 比 `DatabaseQueryException(...)` 更清晰地表達了「創建一個資料庫錯誤」的意圖。
