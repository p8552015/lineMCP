# 自然語言查詢處理流程

本文件說明 LINE MCP Bot 如何處理自然語言查詢。

## 🎯 查詢處理優先順序

系統按以下優先順序處理使用者的自然語言查詢：

### 1. 📝 規則解析（優先）
- **優點**：快速、準確、無成本
- **適用範圍**：常見查詢模式
- **處理時間**：< 50ms

系統首先嘗試使用預定義的規則和模式來理解查詢：

```
支援的查詢模式：
- M001機台狀況如何？ → 特定機台查詢
- 查看所有機台 → 全機台列表
- 近期故障記錄 → 故障分析
- 生產統計報告 → 生產統計
- 加工部狀況 → 部門查詢
```

### 2. 🌟 Google Gemini（規則失敗時）
- **免費額度**：15M tokens/月
- **成本**：$0.075/1K input, $0.30/1K output
- **優勢**：大量免費額度，中文理解能力強

當規則解析無法識別查詢時，系統會使用 Gemini 進行智能理解。

### 3. 🤖 OpenAI GPT（備用）
- **模型**：GPT-4o-mini
- **成本**：$0.15/1M input, $0.60/1M output
- **優勢**：價格最低，效能穩定

當 Gemini 不可用時，系統會使用 OpenAI 的模型。

## 📊 處理流程圖

```
使用者輸入
    ↓
[規則解析]
    ↓
成功？ ─是→ 返回結果
    │
    否
    ↓

    │
    是
    ↓
[Gemini解析]
    ↓

    │
    否
    ↓

    ↓
返回結果或"無法識別"
```

## 🛠️ 配置選項

在 `.env` 文件中設定：

```env
# 啟用/禁用AI增強
AI_ENABLE_ENHANCED_NL=true

# 確保規則優先
AI_RULES_FIRST=true

# AI失敗時回退到規則
AI_FALLBACK_TO_RULES=true
```

## 📈 效能比較

| 方法 | 速度 | 成本 | 準確度 |
|------|------|------|--------|
| 規則解析 | 極快 (<50ms) | 免費 | 高 (90%+) |
| Gemini | 快 (~500ms) | 極低/免費 | 很高 (95%+) |
| OpenAI | 快 (~300ms) | 低 | 很高 (95%+) |

## 🛡️ v5 穩定性修復

### 解決的關鍵問題
- ✅ **空查詢問題**：實施三重驗證機制，確保所有查詢都有有效SQL
- ✅ **類型安全錯誤**：統計服務雙重類型轉換，消除字串與數值比較錯誤
- ✅ **解析器協調**：增強解析器與建構器間的協調機制

### 架構改善
- **自動預設模板載入**：模板缺失時自動載入預設模板
- **錯誤自動恢復**：解析器返回空SQL時自動觸發建構器
- **完整容錯機制**：多層保護確保系統穩定運行

## 💡 最佳實踐

1. **優化規則模式**：定期分析常見查詢，添加新的規則模式
2. **監控AI使用**：追蹤AI調用次數，確保在免費額度內
3. **快取結果**：對相同查詢快取解析結果
4. **錯誤處理**：AI失敗時提供有用的建議
5. **生產監控**：使用 `test_current_fix_status.py` 監控系統健康
