# 任務規劃執行樣板

## 🎯 樣板目標

此樣板提供結構化的任務規劃與追蹤機制，確保專案開發過程中每個任務都能被有效管理和驗證。

## 📋 任務規格執行器機制

任務執行期間，每隔30分鐘自動執行git提交當前版本


### 必須遵守的文件存放規則
將產出的自定義任務名稱.md文件存放於 /Users/yen/Desktop/lineMCP/task/任務規劃書 這個路徑下的資料夾
將計劃中的每個任務測試結果存放於 /Users/yen/Desktop/lineMCP/task/任務測試報告 這個路徑下的資料夾
將計劃中的執行完的完整報告存放於 /Users/yen/Desktop/lineMCP/task/最終報告 這個路徑下的資料夾

### 核心流程
1. **規劃階段**：撰寫 `自定義任務名稱.md` 規格檔案
2. **執行階段**：依任務表逐一執行 TODO 任務
3. **追蹤階段**：任務完成即時回寫狀態到規格檔案
4. **驗證階段**：每個任務都需要通過測試才能繼續
5. **總結階段**：所有任務完成後撰寫專案總結

### 狀態管理
- **TODO**：待執行任務
- **DOING**：進行中任務
- **DONE**：已完成任務
- **BLOCKED**：受阻任務

## 🔧 執行規則

### 必須遵守的規則
1. **任務表區塊保護**：只能修改 `<!-- TASKS START -->` 與 `<!-- TASKS END -->` 之間的內容
2. **狀態更新流程**：
   - 開始任務前：將狀態從 `TODO` 改為 `DOING`
   - 完成任務後：將狀態改為 `DONE` 並填入結束時間
   - 遇到阻礙時：將狀態改為 `BLOCKED` 並註記原因
3. **時間格式**：結束時間使用 `%Y-%m-%d %H:%M` 格式
4. **即時保存**：每次狀態變更後立即保存檔案

### 程式碼品質要求
- **SOLID 原則**：所有程式碼必須符合 SOLID 設計原則
- **程式碼驗證**：使用 Serena MCP Server 確認方法存在性
- **依賴檢查**：確保所有程式碼都有被正確引用

### 問題處理原則
- **審慎修改**：修改任何檔案前必須確認問題根本原因
- **工具驗證**：透過 Serena MCP Server 閱讀相關文件
- **安全優先**：不確定的修改寧可暫停執行

## 🧪 測試驗證流程

### 必要測試
1. **功能測試**：每個任務完成後執行對應測試腳本
2. **系統測試**：運行 `/path/to/start-production.sh` 腳本
3. **核心功能驗證**：
   - M001機台稼動率查詢
   - 所有機台狀態查詢
   - 系統整體健康檢查

### 測試通過標準
- 所有測試腳本執行成功
- 系統核心功能正常運作
- 無關鍵錯誤或異常

## 📁 檔案更新要求

### 必須更新的檔案
1. **專案文件**：反映程式碼變更
2. **啟動腳本**：確保使用最新修復
3. **文檔資料**：保持同步更新

## ⚠️ 錯誤處理機制

### 當任務失敗時
1. 將任務狀態設為 `BLOCKED`
2. 在描述欄位註記失敗原因：`（原因：具體錯誤描述）`
3. 暫停後續任務執行
4. 分析問題根本原因
5. 制定修復方案後重新開始

### 系統異常處理
- 保持檔案完整性
- 記錄異常詳細資訊
- 提供快速恢復機制

## 🚀 快速開始指南

### 3步驟建立新專案任務
1. **複製樣板**：複製此樣板並重新命名為 `spec_你的專案名稱.md`
2. **填寫任務表**：在 `<!-- TASKS START -->` 區塊中填入具體任務
3. **開始執行**：按照狀態管理流程逐一完成任務

## ❓ 常見問題解答

**Q: 任務狀態不小心設錯了怎麼辦？**
A: 直接修改任務表中的狀態欄位，確保保存檔案即可

**Q: 測試失敗了該如何處理？**  
A: 1) 將任務狀態改為 `BLOCKED` 2) 記錄錯誤原因 3) 分析根本原因 4) 修復後重新測試

**Q: 可以跳過某個任務嗎？**
A: 不建議跳過，如果必須跳過請將狀態設為 `BLOCKED` 並說明原因

**Q: 如何處理依賴關係？**
A: 在任務描述中明確標註依賴關係，按順序執行相關任務

## 🔧 故障排除指南

### 系統測試失敗
1. 檢查 start-production.sh 腳本是否存在
2. 確認環境變數設置正確
3. 檢查服務依賴是否正常啟動

### Serena MCP Server 連接問題
1. 確認 MCP 服務器狀態
2. 檢查網路連接
3. 查看錯誤日誌檔案

### 任務執行卡住
1. 檢查是否有 `BLOCKED` 狀態的任務
2. 確認所有依賴任務已完成
3. 查看任務描述是否清楚明確

## 💡 最佳實踐建議

### 任務設計原則
- **具體明確**：任務描述要具體，避免模糊不清
- **可測試**：每個任務都要有明確的完成標準
- **適當粒度**：不要太大也不要太小，一般2-4小時完成

### 狀態管理技巧
- **即時更新**：狀態改變後立即保存檔案
- **詳細記錄**：重要的變更要在描述中註記
- **定期檢查**：定期檢查任務進度和依賴關係
