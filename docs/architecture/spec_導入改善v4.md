## 🔍 問題分析

### 📈 新發現的關鍵問題

基於最新的生產環境錯誤日誌分析，發現以下 4 個關鍵問題：

#### 1. **統計服務類型錯誤重現** ❌
```
查詢解析: ❌ 失敗 - '>=' not supported between instances of 'str' and 'float'
```

**根本原因分析**：
- **問題位置**: v3 修復的 `_safe_float_conversion` 沒有覆蓋所有數值比較場景
- **具體症狀**: 在統計服務的某些方法中，仍然存在字串與浮點數的直接比較
- **影響範圍**: 查詢解析統計記錄功能，導致統計功能部分失效
- **觸發條件**: 當 duration 或 confidence 參數以字串形式傳入時

#### 2. **MCP 回應解析失敗** 🔌
```
JSON 解析失敗:Expecting value: line 1 column 1 (char 0)，原始內容:Error: Only SELECT queries are allowed for read_query
```

**根本原因分析**：
- **問題位置**: `MCPResponseParser` 假設所有回應都是有效 JSON 格式
- **具體症狀**: MCP 服務器回傳錯誤訊息為純文本，不是 JSON 格式
- **影響範圍**: 所有資料庫查詢操作，導致查詢功能完全失效
- **觸發條件**: 當 MCP 服務器拒絕查詢時回傳錯誤文本

#### 3. **SQL 查詢安全限制** 🔒
```
Error: Only SELECT queries are allowed for read_query
```

**根本原因分析**：
- **問題位置**: MCP 服務器端實施了嚴格的 SQL 安全策略
- **具體症狀**: 只允許 SELECT 查詢，拒絕其他類型的 SQL 語句
- **影響範圍**: 可能某些模板包含非 SELECT 操作或子查詢
- **觸發條件**: 當 SQL 模板被錯誤識別為修改操作時

#### 4. **OpenTelemetry 連接失敗** 📡
```
Transient error StatusCode.UNAVAILABLE encountered while exporting traces to localhost:4317
```

**根本原因分析**：
- **問題位置**: OpenTelemetry 配置指向不存在的 OTLP 收集器
- **具體症狀**: 持續重試連接 localhost:4317，產生大量錯誤日誌
- **影響範圍**: 污染系統日誌，影響監控和除錯效率
- **觸發條件**: 當沒有運行 OTLP 收集器服務時

## 🛠️ 詳細修復計劃

### Phase 1: 深度統計服務類型安全修復 (30分鐘)

#### 🎯 修復目標
徹底解決統計服務中所有類型比較錯誤，確保數值運算的完全類型安全。

#### 📋 具體修復步驟

1. **全面類型安全審查** (10分鐘)
   - 檢查 `QueryStatisticsService` 中所有數值比較操作
   - 識別 `get_stats()`, `_calculate_std()`, `_calculate_percentiles()`, `_grade_performance()` 等方法的風險點
   - 找出所有可能接收字串參數的入口點

2. **擴展類型轉換覆蓋範圍** (15分鐘)
   - 擴展 `_safe_float_conversion()` 方法的應用範圍
   - 在所有數值計算入口點添加類型檢查
   - 實現 `_safe_duration_conversion()` 和 `_safe_confidence_conversion()` 專用方法
   - 添加列表和字典中數值的批量轉換功能

3. **增強錯誤處理和日誌** (5分鐘)
   - 為類型轉換失敗提供詳細的診斷信息
   - 記錄轉換失敗的原始值和上下文
   - 實現統計數據完整性驗證

#### 🔍 關鍵修復點
- `record_success()` 和 `record_failure()` 方法的參數驗證
- `get_stats()` 方法中的聚合計算
- 所有統計指標計算中的數值比較操作

### Phase 2: MCP 回應解析器錯誤處理增強 (25分鐘)
