# 程式碼重構執行樣板

## 🎯 樣板目標

此樣板專注於程式碼重構與品質改善，確保重構過程遵循 SOLID 原則並維持系統穩定性。

## 📐 SOLID 原則遵循指南

### S - 單一職責原則 (Single Responsibility Principle)
- **檢查要點**：每個類別或函數只負責一項功能
- **重構策略**：拆分複雜類別，分離關注點
- **驗證方法**：檢查類別變更原因是否單一

### O - 開放封閉原則 (Open/Closed Principle)  
- **檢查要點**：對擴展開放，對修改封閉
- **重構策略**：使用抽象介面和多型
- **驗證方法**：新功能是否需要修改現有程式碼

### L - 里氏替換原則 (Liskov Substitution Principle)
- **檢查要點**：子類別可以替換父類別
- **重構策略**：確保子類別行為一致性
- **驗證方法**：子類別不應該強化前置條件

### I - 介面隔離原則 (Interface Segregation Principle)
- **檢查要點**：客戶端不應依賴不需要的介面
- **重構策略**：拆分過大的介面
- **驗證方法**：檢查介面實現的完整性

### D - 依賴倒置原則 (Dependency Inversion Principle)
- **檢查要點**：依賴抽象而非具體實現
- **重構策略**：使用依賴注入模式
- **驗證方法**：高層模組不依賴低層模組

## 🔧 重構執行流程

### 階段一：重構前分析
1. **程式碼掃描**：使用 Serena MCP Server 掃描目標檔案
2. **依賴分析**：確認所有依賴關係和呼叫鏈
3. **測試基線**：建立重構前的測試基線
4. **備份創建**：建立程式碼備份點

### 階段二：SOLID 原則檢查
1. **SRP 檢查**：分析類別和函數職責
2. **OCP 檢查**：評估擴展性設計
3. **LSP 檢查**：驗證繼承關係
4. **ISP 檢查**：檢查介面設計
5. **DIP 檢查**：確認依賴方向

### 階段三：重構實施
1. **漸進式重構**：小步驟迭代式改進
2. **測試驗證**：每次變更後執行測試
3. **程式碼審查**：使用 Serena MCP Server 驗證
4. **文檔更新**：同步更新相關文檔

### 階段四：重構後驗證
1. **功能測試**：確保功能完整性
2. **效能測試**：驗證效能無顯著下降
3. **整合測試**：確認系統整合正常
4. **回歸測試**：完整的回歸測試套件

## ⚠️ 重構安全原則

### 必須遵守的安全規則
1. **確認問題根因**：修改前必須確定問題真正原因
2. **Serena 驗證**：使用 Serena MCP Server 閱讀相關檔案
3. **方法存在性**：確認所有方法都實際存在
4. **依賴完整性**：確保所有程式碼都有被正確引用

### 風險控制機制
- **小步快跑**：每次只做最小可行變更
- **即時測試**：變更後立即執行測試
- **回滾準備**：準備快速回滾機制
- **同行審查**：重要變更需要同行審查

## 🧪 重構測試策略

### 測試層級
1. **單元測試**：函數層級的測試覆蓋
2. **整合測試**：模組間的整合驗證
3. **系統測試**：端到端功能驗證
4. **回歸測試**：確保無副作用

### 測試腳本範例
```bash
# 執行所有測試
cd apps/bot && poetry run pytest -v

# 特定模組測試
cd apps/bot && poetry run pytest tests/unit/test_specific_module.py -v

# 測試覆蓋率檢查
cd apps/bot && poetry run pytest --cov=src --cov-report=html

# 程式碼品質檢查
cd apps/bot && poetry run black src/
cd apps/bot && poetry run ruff check src/
cd apps/bot && poetry run mypy src/
```

## 📊 重構品質指標

### 程式碼品質指標
- **圈複雜度**：目標 < 10
- **類別大小**：目標 < 200 LOC
- **方法長度**：目標 < 50 LOC
- **重複代碼**：目標 < 3%

### SOLID 符合度指標
- **SRP 符合度**：> 90%
- **OCP 符合度**：> 85%
- **LSP 符合度**：> 95%
- **ISP 符合度**：> 90%
- **DIP 符合度**：> 80%

## ❓ 重構常見問題

**Q: 重構過程中測試失敗怎麼辦？**
A: 立即停止重構，分析失敗原因，回滾到上一個穩定狀態

**Q: 如何確保重構不引入新問題？**
A: 使用 TDD 方法，先寫測試再重構，確保行為不變

**Q: 重構範圍如何控制？**
A: 遵循最小變更原則，每次只重構一個 SOLID 原則

**Q: 如何處理複雜的依賴關係？**
A: 使用依賴圖分析，從葉子節點開始重構
