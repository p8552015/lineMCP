## 詳細時序圖

### 1. 正常查詢流程（有效SQL查詢）

```mermaid
sequenceDiagram
    participant U as LINE用戶
    participant L as LINE Platform
    participant W as Webhook接收器
    participant M as MessageHandlerDI
    participant A as ApplicationFacade
    participant N as NL-to-SQL Service
    participant P as AI Enhanced Parser
    participant AI as EnhancedAIModelService
    participant G as Gemini API
    participant O as OpenAI API
    participant MCP as PostgreSQL MCP
    participant DB as PostgreSQL DB

    U->>L: 發送訊息："M001機台狀態"
    L->>W: POST /webhook
    W->>M: 處理LINE事件
    M->>A: handle_message()
    
    Note over A: 統一應用入口
    A->>N: parse_natural_language(text="M001機台狀態")
    
    Note over N: 輸入驗證階段
    N->>N: _validate_input()
    N-->>N: ✅ 驗證通過
    
    Note over N: SOLID解析器階段
    N->>P: parse(text, context)
    P->>P: 規則解析器嘗試
    P-->>P: ❌ 規則無法處理
    
    Note over P: AI增強解析
    P->>AI: enhance_natural_language_query()
    
    Note over AI: 模型選擇與重試機制
    AI->>AI: 檢查模型健康狀態
    AI->>AI: 選擇主要模型 (Gemini)
    
    AI->>G: 調用Gemini API
    G-->>AI: 🟢 成功回應 (JSON格式)
    AI-->>P: 返回增強查詢結果
    
    P-->>N: ParsedQuery{type=MACHINE_STATUS}
    
    Note over N: SQL建構階段
    N->>N: _get_query_builder()
    N->>N: build_query(MACHINE_STATUS, params)
    N-->>N: ✅ SQL生成成功
    
    Note over N: 資料庫查詢階段
    N->>MCP: call_tool("postgres", "query", sql)
    MCP->>DB: 執行SQL查詢
    DB-->>MCP: 返回查詢結果
    MCP-->>N: 資料記錄
    
    N-->>A: 完整查詢結果
    A-->>M: 格式化回應
    M-->>W: 發送回應
    W->>L: 回應LINE用戶
    L->>U: 顯示機台狀態資料
```

## 關鍵技術細節

### 1. 依賴注入架構
```
ApplicationFacade → IServiceFactory ← EnhancedServiceFactory
                                    ↙   ↓   ↘
                     CoreServices  App   Infrastructure
                     Registry     Services   Services
                                 Registry   Registry
```

### 2. AI模型備用機制
- **主要模型**: Gemini 1.5 Flash (15M免費tokens/月)
- **備用模型**: OpenAI GPT-4o-mini
- **切換觸發**: HTTP 429, "quota", "resource_exhausted" 錯誤
- **健康檢查**: 失敗次數、配額狀態、最後成功時間

### 3. 查詢類型處理
- **MACHINE_STATUS**: 機台狀態查詢
- **PRODUCTION_STATS**: 生產統計
- **FAULT_ANALYSIS**: 故障分析
- **ALL_MACHINES**: 全部機台概覽
- **DEPARTMENT_STATUS**: 部門狀態
- **UNKNOWN**: 觸發LLM用戶指導

### 4. 錯誤處理層級
1. **輸入驗證**: 長度、格式、安全性檢查
2. **解析錯誤**: 規則解析失敗 → AI增強解析
3. **AI錯誤**: 主模型失敗 → 備用模型切換
4. **SQL錯誤**: 建構失敗 → 用戶指導
5. **資料庫錯誤**: MCP連接失敗 → 自動重連

## 性能指標

- **平均回應時間**: < 1ms (本地處理)
- **AI API調用**: 1-3秒 (含重試)
- **資料庫查詢**: < 100ms
- **系統啟動時間**: < 30秒
- **MCP連接檢查**: < 5秒
- **備用模型切換**: < 500ms

## 監控與日誌

- **結構化日誌**: structlog格式
- **統計追蹤**: 成功率、回應時間、錯誤分布
- **健康監控**: 模型狀態、連接池狀態
- **效能指標**: 吞吐量、延遲百分位
- **錯誤告警**: 配額用盡、連線失敗、服務異常
