## 🧩 樣板 1：檔案在專案中扮演的角色

```
serena 告訴我這個文件 {{file_path}}（可以是其他的文件）在專案中扮演的角色

請依照下列結構輸出，根據檔案實際內容選填：

【文件角色摘要】
- 📌 主要功能與責任：
- 🧠 在系統架構中的定位（上層來源與下游依賴）：
- 🔁 是否處理通訊 / 外部互動（如子進程、API、message queue）：
- ⚙️ 是否處理設定管理（設定檔、環境變數、flags）：
- 🧪 是否負責資料驗證、格式轉換或協定解析：
- 💡 是否涉及平台相依性、跨平台兼容性、錯誤恢復：
- 🔐 是否與授權、安全、敏感操作有關：
- 🎯 實用比喻（若適合，提供類比幫助理解）：
```

## 🧩 樣板 2：有哪些類別，以及創建目的與結構特性

```
serena 告訴我這個文件 {{file_path}} 中有哪些類別，以及創建這些類別的目的

請依照下列格式為每個類別提供分析：

【類別分析】
- 類別名稱：`{{ClassName}}`
- 📌 創建目的：
- 🧭 使用場景（由誰使用、何時初始化）：
- 📂 管理資源（如連線、檔案、程序、佇列等）：
- 🧩 內含哪些關鍵方法與邏輯功能（可列出 method list）：
- 🔄 是否支援擴充或注入（如 plugin、callback、hook）：
- ⚙️ 是否耦合其他模組或設定來源（設定路徑、DB schema 等）：
- 💡 設計考量（如封裝、SRP、LSP、DI、可測試性）：
- ✅ 是否容易測試 / 是否有測試機制設計（mock/inject/fake）
```

## 🧩 樣板 3：所有方法分析、使用情況與價值評估

```
serena 告訴我這個文件 {{file_path}} 中所有的方法，以及它們的目的、實際使用地方、使用次數、被引用次數，並判斷其存在價值

請以表格及附註說明回覆，並補上系統與資源觀點：

【方法總覽】

| 方法名稱 | 功能簡述 | 是否為關鍵邏輯 | 內部使用次數 | 外部被呼叫 | 錯誤處理 | 資源釋放 | 存在價值 |
|----------|----------|----------------|----------------|--------------|-----------|-------------|------------|

【模組層級函式】

| 函式名稱 | 功能用途 | 使用情境 | 是否必要 | 替代方式 | 存在價值 |
|----------|----------|------------|------------|-------------|-------------|

【補充分析】
- 🔄 是否支援 retry / fallback / timeout
- 🔁 是否非同步 async / 並行 queue / 多線程保護
- 📊 測試覆蓋情況（若已知）
- 🚨 是否為效能瓶頸或熱點（如 loop 中呼叫 I/O）
- 🧼 是否有清理 / close / dispose 等機制
```
