# 代碼審查與生命週期管理流程

## 🎯 目標
建立系統化的代碼健康監控機制，防止技術債務累積，確保代碼庫的長期可維護性。

## 📋 核心原則

### 1. 6個月生命週期原則
- **定義**: 任何未被引用的代碼項目，如果在6個月內沒有被啟用，將被標記為候選移除
- **例外**: 具有明確業務價值的預留功能可以標記保留
- **評估週期**: 每月執行一次生命週期檢查

### 2. 預留代碼管理
- **文檔要求**: 所有預留代碼必須有明確的保留理由
- **審查機制**: 每季度重新評估保留理由的有效性
- **決策記錄**: 使用 ADR (Architecture Decision Record) 追蹤重要決策

## 🔧 工具使用

### 代碼生命週期管理器 (`code_lifecycle_manager.py`)

#### 安裝與配置
```bash
# 賦予執行權限
chmod +x code_lifecycle_manager.py

# 首次掃描
python code_lifecycle_manager.py --project-root /path/to/project --scan
```

#### 常用命令

**1. 掃描更新**
```bash
# 掃描並更新追蹤數據
python code_lifecycle_manager.py --scan

# 生成報告
python code_lifecycle_manager.py --report
```

**2. 標記保留**
```bash
# 標記重要的預留功能
python code_lifecycle_manager.py --mark-retention \
  "config/mcp_config.py" "add_server_config" "未來管理後台需要"

python code_lifecycle_manager.py --mark-retention \
  "utils/observability.py" "get_telemetry_health" "健康檢查診斷功能"
```

**3. 生成報告**
```bash
# 生成當前狀態報告
python code_lifecycle_manager.py --report > monthly_code_review.md
```

## 📅 定期流程

### 月度代碼審查 (每月第一個週五)

**1. 數據更新 (5分鐘)**
```bash
cd /path/to/project
python code_lifecycle_manager.py --scan
```

**2. 報告生成 (2分鐘)**
```bash
python code_lifecycle_manager.py --report
```

**3. 審查決策 (30分鐘)**
- 檢查候選移除項目列表
- 評估每個項目的業務價值
- 標記需要保留的項目
- 制定移除計劃

**4. 執行清理 (15分鐘)**
- 移除確認無用的代碼
- 更新相關文檔
- 執行測試確保無破壞性

### 季度深度審查 (每季度最後一週)

**1. 保留理由重新評估**
- 檢查所有已標記保留的項目
- 評估保留理由是否仍然有效
- 更新或移除過時的保留標記

**2. 架構債務評估**
- 識別代碼異味和架構問題
- 制定重構計劃
- 優先級排序

**3. 工具改進**
- 收集使用反饋
- 改進檢測規則
- 更新流程文檔

## 🎨 代碼保留分類

### A類 - 立即保留 (無條件)
- **API介面**: 對外提供的公開介面
- **核心業務邏輯**: 直接影響業務功能
- **安全機制**: 認證、授權、加密相關
- **監控診斷**: 系統健康檢查功能

**範例**:
```python
# 健康檢查API - A類保留
def get_telemetry_health() -> dict:
    """系統遙測健康狀況檢查"""
    pass
```

### B類 - 條件保留 (需要業務確認)
- **管理功能**: 未來可能需要的管理介面
- **擴展接口**: 為未來功能預留的抽象
- **配置管理**: 動態配置相關功能
- **整合準備**: 為第三方整合預留的功能

**範例**:
```python
# MCP配置管理 - B類保留 (管理後台需要)
def add_server_config(self, config: dict) -> bool:
    """添加MCP服務器配置"""
    pass
```

### C類 - 候選移除 (優先清理)
- **實驗性功能**: 已停止開發的實驗功能
- **重複實現**: 有更好替代方案的舊實現
- **臨時工具**: 一次性使用的臨時代碼
- **調試代碼**: 開發期間的調試輔助

## 📊 品質指標

### 代碼健康度指標
- **活躍代碼比例**: 目標 > 90%
- **未使用代碼**: 目標 < 5%
- **保留代碼**: 目標 < 3%
- **移除響應時間**: 目標 < 7天

### 審查效率指標
- **月度審查時間**: 目標 < 1小時
- **誤標率**: 目標 < 5%
- **自動化程度**: 目標 > 85%

## 🚨 異常處理

### 誤刪情況
1. **立即回滾**: 使用Git恢復誤刪代碼
2. **根因分析**: 分析誤刪原因
3. **流程改進**: 改進檢測規則和審查流程
4. **標記保留**: 確保類似代碼不再被誤刪

### 爭議解決
1. **技術評估**: 由技術負責人評估爭議代碼
2. **業務確認**: 與產品負責人確認業務需求
3. **決策記錄**: 使用ADR記錄決策過程
4. **定期重審**: 3個月後重新評估決策
