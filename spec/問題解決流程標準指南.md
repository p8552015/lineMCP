# 問題解決流程標準指南
**版本**: v1.0  
**日期**: 2025-06-30  
**適用範圍**: LINE MCP Bot 系統開發與維護

## 📋 指南概述

本指南基於實際解決「測試環境正常，生產環境異常」問題的完整經驗，提供標準化的問題分析和解決流程，避免重複犯相同錯誤。

## 🚨 典型問題場景

### 常見症狀
- ✅ 測試環境功能正常
- ❌ 生產環境出現異常行為
- 🔄 修復後問題依然存在
- 📝 語法錯誤已修復但系統行為未改變

### 實際案例 (2025-06-30)
**問題**: "CNC車床今天不良率" 查詢返回技術性描述而非友善 LLM 指導
- 測試腳本: 返回自然友善回應 ✅
- Web API: 返回技術性描述 ❌

## 🔍 第一階段：問題診斷

### 1.1 確認問題範圍

### 1.2 分離測試環境與生產環境
```bash

cd apps/bot && python test_direct.py

# Web API 測試 (生產環境)
curl -X POST http://localhost:8000/test-llm \
  -H "Content-Type: application/json" \
  -d '{"text":"測試查詢"}'
```

### 1.3 識別問題類型
- **代碼同步問題**: 新代碼未載入到生產環境
- **服務單例快取**: 舊版本服務實例被快取
- **方法路由錯誤**: 調用路徑指向舊版本方法
- **環境差異**: 配置或依賴版本不同

## ⚡ 第三階段：修復實施

### 3.1 修復優先順序
1. **語法錯誤** (阻塞性)

3. **服務註冊** (架構性)
4. **調用路徑** (整合性)

### 3.2 修復驗證流程
```bash

python -m py_compile 目標文件.py

# 2. 單元測試

# 4. 服務重啟
pkill -f uvicorn
./start-production.sh

# 5. 完整驗證
./quick-test-vocabulary.sh
```

### 3.3 修復模式

#### 模式一：方法覆寫
```python
# 在增強版服務中覆寫基類方法
class EnhancedAIModelService(AIModelService):
    async def generate_user_guidance(self, ...):
        # 🔥 增強版實現（支援備用模型）
        for model in target_models:
            if not self._is_model_healthy(model):
                continue
            try:
                result = await self._call_model(...)
                return result
            except Exception as e:
                # 處理錯誤並切換模型
                continue
```

#### 模式二：服務工廠更新
```python
# 確保註冊正確的服務實現
registry.register(
    service_type=AIModelService,
    implementation=EnhancedAIModelService,  # 使用增強版
    scope=ServiceScope.SINGLETON
)
```

## 📊 成功案例分析

### 案例：LLM 指導修復 (2025-06-30)

#### 問題症狀
- 測試環境：友善的 LLM 指導 ✅
- 生產環境：技術性描述 ❌

#### 根本原因
1. `generate_user_guidance` 方法在基類中沒有備用模型支援
2. Web 服務使用單例快取了舊版本服務實例
3. Gemini 配額用盡時沒有正確切換到 OpenAI

#### 解決步驟
1. ✅ 修復語法錯誤
2. ✅ 在 `EnhancedAIModelService` 中實現支援備用模型的方法
3. ✅ 驗證直接測試正常
4. ✅ 停止並重啟服務
5. ✅ 驗證 Web API 正常

#### 關鍵學習
- **方法覆寫**: 增強版服務必須完整實現所有新功能
- **服務重啟**: 修改核心服務後必須重啟以清除快取
- **多層測試**: 直接測試 + Web API 測試缺一不可
