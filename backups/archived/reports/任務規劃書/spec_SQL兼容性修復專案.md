## 問題背景

### 問題描述
在系統運行過程中發現 SQL 兼容性問題：
- **錯誤訊息**: `function date(unknown, unknown) does not exist`
- **根本原因**: SQL 模板使用了 MySQL 語法而非 PostgreSQL 語法
- **影響範圍**: 故障分析查詢無法執行，影響 LINE Bot 查詢功能

### 問題分析
1. **語法差異**: MySQL 使用 `date('now', '-7 days')`，PostgreSQL 使用 `CURRENT_DATE - INTERVAL '7 days'`
2. **影響文件**: 發現 14 個文件中共 20+ 處使用了不兼容語法
3. **核心影響**: 
   - SQL 模板無法正確執行
   - 自然語言查詢失敗
   - 機台故障分析功能異常

## 專案目標

### 主要目標
1. **修復 SQL 語法兼容性問題**，確保所有查詢在 PostgreSQL 中正常運行
2. **建立 PostgreSQL 標準化模板**，避免未來類似問題
3. **驗證修復效果**，確保所有功能正常運作

### 語法對照表
| MySQL 語法 | PostgreSQL 語法 | 說明 |
|-----------|----------------|------|
| `date('now', '-7 days')` | `CURRENT_DATE - INTERVAL '7 days'` | 日期計算 |
| `date('now', '-{days} days')` | `CURRENT_DATE - INTERVAL '{days} days'` | 動態日期計算 |
| `DATE('now')` | `CURRENT_DATE` | 當前日期 |
| `DATE(column)` | `column::date` | 日期轉換 |

## 解決方案設計

### 修復策略
1. **階段一：核心模板修復** (優先級：高)
   - 修復 `sql_templates.yaml` 中的所有不兼容語法
   - 修復 `query_template_manager.py` 中的預設模板
   
2. **階段二：服務層修復** (優先級：高)
   - 修復 `database_service.py` 中的查詢語法
   - 更新相關服務中的 SQL 語句

3. **階段三：測試修復** (優先級：中)
   - 修復測試文件中的 SQL 語法
   - 確保測試案例使用正確語法

4. **階段四：驗證與優化** (優先級：中)
   - 功能驗證測試
   - 建立語法檢查機制

### 技術實作方案
```sql
-- 修復前 (MySQL 語法)
WHERE fault_date >= date('now', '-7 days')
AND u.date >= date('now', '-{days} days')

-- 修復後 (PostgreSQL 語法)  
WHERE fault_date >= CURRENT_DATE - INTERVAL '7 days'
AND u.date >= CURRENT_DATE - INTERVAL '{days} days'
```
