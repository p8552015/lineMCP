# T-05 環境變數一致性檢查報告

## 🎯 檢查目標
分析CI配置文件中所有job的環境變數設置，確保關鍵環境變數在各個job中的一致性，特別關注 `GOOGLE_API_KEY` 的缺失問題。

## 🔍 分析結果

### 環境變數使用統計
通過Serena MCP搜尋分析發現以下環境變數在CI中的使用情況：

| 環境變數 | 單元測試 | 整合測試 | 架構測試 | nodecomman測試 | 覆蓋率測試 | 狀態 |
|---|---|---|---|---|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | ✅ | ✅ | ✅ | ✅ | ✅ | 一致 |
| `AI_MODEL_PROVIDER` | ✅ | ✅ | ✅ | ✅ | ✅ | 一致 |
| `ASYNCIO_FORCE_SELECT_SELECTOR` | ✅ | ✅ | ✅ | ✅ | ❌ | **不一致** |
| `GOOGLE_API_KEY` | ❌ | ❌ | ❌ | ❌ | ❌ | **完全缺失** |
| `OPENAI_API_KEY` | ❌ | ❌ | ❌ | ❌ | ❌ | **完全缺失** |
| `DATABASE_URL` | ❌ | ✅ | ❌ | ❌ | ❌ | 部分使用 |

## 🚨 關鍵問題發現

### 1. GOOGLE_API_KEY 完全缺失
- **問題**: 所有CI job都沒有設置 `GOOGLE_API_KEY`
- **風險**: AI模型調用會失敗，導致測試無法正常執行
- **影響範圍**: 5個job (unit-tests, integration-tests, architecture-tests, nodecomman-tests, coverage-report)

### 2. OPENAI_API_KEY 完全缺失  
- **問題**: 所有CI job都沒有設置 `OPENAI_API_KEY`
- **風險**: 備用AI模型無法使用
- **影響範圍**: 5個job

### 3. ASYNCIO_FORCE_SELECT_SELECTOR 不一致
- **問題**: coverage-report job缺少此環境變數
- **風險**: macOS兼容性問題可能影響覆蓋率報告
- **影響範圍**: 1個job (coverage-report)

## 📊 詳細環境變數分析

### 正確設置的變數
```yaml
# 所有job都正確設置
LINE_CHANNEL_ACCESS_TOKEN: test_token_*  # 各job使用不同值，符合隔離原則
AI_MODEL_PROVIDER: google                # 統一使用google提供商
```

### 缺失的關鍵變數
```yaml
# 需要添加到所有job
GOOGLE_API_KEY: ${{ secrets.GOOGLE_API_KEY }}     # Google Gemini API金鑰
OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}     # OpenAI API金鑰（備用）
```

### 部分使用的變數
```yaml
# DATABASE_URL 僅在integration-tests使用
DATABASE_URL: postgresql://admin:admin@localhost:5432/mydb
# 其他需要資料庫的測試可能也需要此變數
```

## 🔐 Secrets 配置要求

### GitHub Secrets 必需清單
確保以下secrets已在GitHub repository中配置：

1. `GOOGLE_API_KEY` - Google Gemini API金鑰
2. `OPENAI_API_KEY` - OpenAI API金鑰 (備用)
3. `LINE_CHANNEL_ACCESS_TOKEN` - LINE Bot存取權杖 (生產環境)
4. `LINE_CHANNEL_SECRET` - LINE Bot頻道密鑰

```bash

gh secret list
```

## ⚠️ 風險評估

### 高風險問題
1. **AI模型調用失敗** - 缺少API金鑰導致測試無法執行
2. **測試環境不一致** - 不同job的環境差異可能導致難以重現的問題
3. **macOS兼容性** - 缺少ASYNCIO設置可能在某些環境下導致掛起

### 中風險問題
1. **備用模型不可用** - 僅Google API可用，OpenAI備用失效
2. **除錯困難** - 環境不一致增加問題排查複雜度
