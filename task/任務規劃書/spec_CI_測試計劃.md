# CI 測試計劃規格文件

## 📋 專案概述

### 專案名稱
LINE MCP 智慧製造監控系統 - CI/CD 測試計劃制定

### 專案目標
根據現有的 ci-enhanced.yml 配置，制定全面的 CI 測試計劃，確保系統的穩定性、安全性和效能。

### 專案範圍
- 分析現有 CI 配置的測試覆蓋範圍
- 識別測試缺口並制定改進方案
- 設計完整的測試策略和執行計劃
- 創建標準化的測試報告模板

### 預期成果
- 完整的 CI 測試計劃文檔
- 測試覆蓋率提升至 100%
- 標準化的測試流程和報告格式
- 自動化測試執行機制

## 🏗️ 系統架構分析

### 現有 CI 配置概述
基於 `.github/workflows/ci-enhanced.yml` 的分析：

#### 1. Python 測試與覆蓋率 (python-tests)
- **執行環境**: Ubuntu latest, Python 3.11
- **測試範圍**: 
  - 單元測試 (pytest)
  - 程式碼覆蓋率 (65% 門檻)
  - 程式碼風格檢查 (Black, Ruff)
- **服務依賴**: Redis 7-alpine

#### 2. MCP 整合測試 (mcp-integration-tests)
- **測試重點**: MCP 客戶端連接和查詢功能
- **測試檔案**:
  - `test_mcp_connection.py`
  - `test_mcp_queries.py`
- **背景服務**: SQLite MCP server

#### 3. API 整合測試 (api-integration-tests)
- **測試範圍**:
  - API 端點測試
  - Webhook 功能測試
- **應用啟動**: FastAPI on port 8000

#### 4. Docker 構建與安全掃描 (docker-build)
- **構建驗證**: Docker image 構建
- **安全掃描**: Trivy 漏洞掃描
- **輸出格式**: SARIF 報告

#### 5. 測試總結 (test-summary)
- **彙整所有測試結果**
- **生成 GitHub Step Summary**
- **失敗時阻擋合併**

## 🔍 測試驗證標準

### 單元測試標準
```python
# 測試命名規範
def test_<被測試功能>_<測試場景>_<預期結果>():
    # Given: 準備測試資料
    # When: 執行測試動作
    # Then: 驗證預期結果
```

### 整合測試標準
- 真實服務依賴（Redis, PostgreSQL）
- 完整的請求/回應週期
- 錯誤場景覆蓋

### E2E 測試標準
- 模擬真實使用者操作
- 跨服務互動驗證
- 系統整體行為確認

## 🚨 風險管理

### 識別的風險
1. **測試環境不一致**
   - 緩解：使用 Docker 容器化測試環境
   
2. **外部服務依賴**
   - 緩解：使用 Mock 和 Stub 進行隔離

3. **測試資料管理**
   - 緩解：建立測試資料生成機制

### 應變計劃
- 測試失敗自動回滾
- 關鍵測試優先執行
- 並行測試失敗隔離
